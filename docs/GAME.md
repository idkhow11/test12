# 게임 설계 (대전 화면, 실시간 조작, AI 조작기, 설정, 소리, 모래 모드)

> 2026-10-04 시작, 10-11 갱신. 10-04에 범위가 "게임 전체도 개발"로 바뀌었다(PROGRESS 0.2). 규칙의 기준은 [RULES.md](RULES.md), AI의 배치 고르기와 모델은 [TRAINING.md](TRAINING.md), 모델 입출력은 [MODEL_IO.md](MODEL_IO.md)다. 이 문서는 그 위에 얹는 **게임**(화면, 입력, 실제 시간 진행, AI가 사람처럼 조작하기, 난이도·페르소나, 설정, 소리, 모래 모드)을 정한다. `[초안]`은 플레이 테스트로 바꿀 값이다. 화면의 자세한 크기·색·효과 시간은 각 클래스의 주석에 있다.

## 1. 범위

| 들어감 | 들어가지 않음 |
|---|---|
| **세 모드:** 사람 대 AI(난이도 5단계 × 페르소나, AI 속도 50~150%), 혼자 연습, 모래 모드 | AI끼리 관전(10-06에 만들었다가 지움, 사용자 결정), 2인 키보드 대전, 네트워크 대전(뒤로 미룸), 리플레이, 과제 7·9·10번 |
| 2인 보드 화면, 고스트, 미리보기 5개, 홀드, 받을 방해 줄 막대, 통계, 예측 승률 막대(보정층 포함), 화면 효과, K.O., 결과 카드 | |
| 설정 화면(6갈래: 조작·감도·화면·효과·소리·AI 속도), 도움말, 효과음, 전적·최고 기록, 메뉴 기억 | |

- **사람 대 AI:** 사람이 P1(왼쪽), AI가 P2(오른쪽)다.
- **혼자 연습:** 플레이어 하나와 방해 줄 공급기다. 블록 속도(중력 상한)와 방해 줄을 고른다.
- **모래 모드:** 혼자 하는 끝없는 판이다. 블록이 고정되면 같은 색 모래로 부서진다(10장).

옛 `Board`, `Shape`, `Tetrominoes`, `Tetris`(분기점 1 이전의 1인용 화면)는 지웠다(10-04 결정). git 기록에는 남는다.

## 2. 구조

```
core      규칙: 시간 없는 GameModel, 배치 탐색, 고정 처리. TimedPlayer·TimedMatch = 실제 시간 규칙 (RULES 6.3, 12.3)
ai        Brain(배치 고르기), AiController(생각 지연·초당 입력 안에서 조작), Prefetch(생각 지연 동안 미리 고르기),
          AiCatalog(난이도·페르소나 → 모델 파일, models/manifest.json), WinRate·WinCalibration(예측 승률과 보정층)
ui        Swing 화면: 창(TetrisApp), 메뉴, 대전 화면, 모래 화면, 설정, 도움말. 판 진행 GameSession·SandSession
sand      모래 모드 규칙 (sand-0.3). sand/ai 는 규칙을 재는 도구용 모래 AI (게임에는 붙이지 않음)
audio     효과음: 코드 합성음 + CC0 녹음 13개 (8장)
settings  사용자 설정, 키 묶음, 전적·최고 기록, 저장 파일
train     MatchRunner·MatchMain(블록 동기 학습 대전), TimedRecorder(실시간 기록, 사람 판 기록)
```

- **규칙과 화면을 나눈다.** `TimedMatch`는 화면 없이 1ms 틱으로 돈다. 화면은 실제 시간이 흐른 만큼 틱을 돌리고 상태를 그린다. 같은 코드가 헤드리스 시험(가상 시간 모드)에서도 돈다.
- **결정론.** 같은 시드, 같은 입력 열이면 같은 결과가 나온다(사람 입력은 틱 번호와 함께 들어간다). AI의 고르기 난수는 학습 대전과 같은 스트림(`Chooser`, 101·102)을 쓴다.
- **스레드.** 판마다 게임 진행 스레드 하나가 판을 바꾼다. 바꾸는 순간(한 틱에 몇 마이크로초)만 판의 잠금을 잡고, 화면은 같은 잠금을 잡고 읽어 그린다. AI의 배치 고르기, 승률 예측, 기록 쓰기는 잠금 밖에서 한다.

## 3. 실제 시간 규칙 (RULES 6.3 확정분)

RULES 6.3의 `[초안]`을 아래처럼 정한다. RULES 6.3에도 같은 내용을 옮겼다.

### 3.1 한 틱 (1ms)

한 플레이어의 한 틱은 **입력 → 중력 → 락 딜레이** 순서다(RULES 12.3).

1. **입력:** 조작 하나(없을 수도 있음). `L`, `R`, `CW`, `CCW`, `D`(한 칸), `HD`(하드드롭), `H`(홀드). 하드드롭은 그 자리에서 고정하고 이번 틱의 나머지(중력, 락 딜레이)는 하지 않는다. 홀드는 블록 하나당 한 번이고, 성공하면 새 블록이 스폰 상태로 나온다(RULES 4장).
2. **중력:** `acc += g`(소프트드롭을 누르고 있으면 `max(g, 20000)`). `acc ≥ 1,000,000`이면 `acc −= 1,000,000`하고 한 칸 내린다(한 틱에 많아야 한 칸). 바닥에 닿아 있으면 `acc = 0`.
3. **락 딜레이:** 아래 3.2.

### 3.2 락 딜레이

| 항목 | 정함 |
|---|---|
| 타이머 시작 | 블록이 **바닥에 닿지 않은 상태에서 닿은 상태로 바뀔 때** 500ms로 놓는다. 스폰하자마자 바닥에 닿아 있으면 스폰 때 놓는다 |
| 줄어듦 | 바닥에 닿아 있는 틱마다 1씩. 0이 되는 틱에 고정한다(바닥에 닿은 지 500틱째) |
| 떨어졌다가 다시 닿음 | 떨어져 있는 동안 타이머는 멈추고, 다시 닿을 때 500ms로 다시 놓는다. 리셋 횟수는 늘지 않는다 |
| 리셋 | 바닥에 닿은 상태에서 이동·회전에 **성공**하면 타이머를 500ms로 되돌리고 리셋 횟수 +1. 실패한 조작은 아무것도 바꾸지 않는다(RULES 6.1) |
| 15회 | 리셋 횟수가 15가 되면, 그 뒤로는 바닥에 닿아 있는 틱의 끝에 바로 고정한다. **15번째 리셋은 시간을 주지 않는다** |
| 리셋 횟수 되돌림 | 블록의 가장 아래 칸의 행 번호가 그 블록의 최댓값보다 커지면 0으로 |

- 스폰 지연, 줄 삭제 지연은 0ms(RULES 6.3).
- **T-spin:** 사람이 둔 블록도 고정할 때 RULES 8장으로 판정한다. 중력으로 내려가거나 `D`로 내려가면 "마지막 조작"이 이동이 되고, 거리 0인 하드드롭은 바꾸지 않는다(RULES 6.1). 그래서 회전으로 끼운 뒤 바로 하드드롭하거나 락 딜레이로 고정하면 T-spin이 된다.

### 3.3 두 플레이어 (RULES 12.3)

- 한 틱에 P1을 처리한 뒤 P2를 처리한다. 틱 안에서 생긴 송신은 **틱이 끝날 때** 상대 대기열에 붙인다.
- 패배는 두 플레이어의 처리가 끝난 뒤 판정한다. 같은 틱에 둘 다 지면 무승부.
- **중력 단계:** 판 시작 후 30초마다 한 단계(RULES 6.3 표), 그 판의 상한까지. 상한은 고른 난이도로 정하고 두 플레이어에게 같다(PLAN 7장).
- **혼자 연습:** 플레이어 하나와 방해 줄 공급기. 공급기는 `없음`, `조금씩`(`S-3`), `섞어서`(`S-mix`)(RULES 13장) 중 고른다. 블록 속도는 아주 느리게·느리게·보통·빠르게·아주 빠르게·최고 속도(초당 1·2·3·5·8·12칸, 처음은 보통)에서 고르고, 그 값이 중력 상한이 된다.

## 4. 사람의 입력

| 동작 | 기본 키 | 처리 |
|---|---|---|
| 왼쪽 / 오른쪽 | ← / → | 누르는 틱에 한 번, **DAS**(기본 170ms) 뒤부터 **ARR**(기본 50ms)마다 반복. 반대쪽을 누르면 나중에 누른 쪽만 |
| 소프트드롭 | ↓ | 누르고 있는 동안 중력 `max(g, 20000)` (RULES 6.3) |
| 하드드롭 | Space | 누를 때 한 번 |
| 시계 회전 | ↑ 또는 X | 누를 때 한 번 |
| 반시계 회전 | Z 또는 Ctrl | 누를 때 한 번 |
| 홀드 | C 또는 Shift | 누를 때 한 번 |
| 일시정지 | P | 세 모드 모두 멈춤과 계속을 바꾼다(4.2) |
| 메뉴·기권 | Esc | 혼자 연습·모래 모드는 바로 메뉴로, 사람 대 AI는 2초 안에 두 번이면 기권(4.2). 결과 카드에서는 메뉴로 |
| 다시 하기 | Enter 또는 R | 결과 카드에서(4.1) |
| 전체 화면 | F11 | 창 어디서나(메뉴·설정 포함) 테두리 없는 전체 화면을 켜고 끈다. 누르고 있어도 한 번만 바꾼다. 켠 채 시작하려면 설정의 '전체 화면으로 시작'을 켜거나 `.\gradlew.bat run "-Dtetris.fullscreen=true"`(PowerShell에서는 따옴표가 필요하다). 창이 화면보다 크면 처음부터 최대화한다 |

- **키는 설정 화면에서 바꾼다(7.4).** 동작마다 키 1~3개이고, 한 키는 한 동작에만 묶인다. 다른 동작이 쓰던 키를 고르면 두 동작의 키를 맞바꾸고 알린다. 한/영, Alt 같은 키는 쓸 수 없다. 전체 화면 키에는 Shift·Ctrl을 쓸 수 없다. 세 모드가 같은 키를 쓴다.
- **DAS는 50~300ms(10ms 단위), ARR은 0~150ms(5ms 단위)** 로 바꿀 수 있다. ARR 0은 틱마다 한 칸(가장 빠름)이다.
- 키 입력은 Swing `KeyEvent`로 받아 "눌림/뗌" 상태를 갱신하고, 틱을 돌릴 때 그 상태에서 조작을 만든다(한 틱에 조작 하나, RULES 12.3).
- 키 반복(운영체제의 자동 반복)은 **모든 키에서** 무시하고(누른 키는 뗄 때까지 다시 누른 것으로 치지 않는다) DAS/ARR만 쓴다. 그래서 Space를 누르고 있어도 하드드롭은 한 번이다.
- 시작 카운트다운(3·2·1) 동안 누른 게임 키는 버린다. 다만 그동안 누르고 있던 ←/→/↓는 GO 직후 바로 움직이고 DAS가 시작된다. 하드드롭·회전·홀드는 넘기지 않는다(GO 직후 뜻하지 않은 하드드롭을 막는다).
- 게임 화면과 메뉴는 입력기(IME)를 끈다. 한/영이 '한'이어도 Z·X·C·P가 입력기에 먹히지 않는다.

### 4.1 결과 카드와 한 판 더

- 판이 끝나면 K.O. 연출 뒤 **1.0초에 결과 카드**가 뜨고, **1.15초부터 키를 받는다**. 판 끝에 누르던 키가 카드로 넘어가지 않게 하려는 것이다.
- 단추는 셋이다: **다시 하기 · 같은 판 다시 · 메뉴로.** ←→로 고르고 Enter로 고른 단추를 정한다. R은 고른 단추와 상관없이 언제나 '다시 하기', Esc는 언제나 '메뉴로'다. 마우스는 카드가 키를 받기 시작한 뒤부터 고르고 누른다. 카드 아래 안내는 지금 키 묶음을 따른다(기본 '← → 고르기 · Enter 확인 · R 다시 하기 · Esc 메뉴로').
- **다시 하기**는 같은 설정에 새 시드다. **같은 판 다시**는 같은 시드·난이도·페르소나·AI 속도라, 사람 입력이 같으면 똑같은 판이 된다(시험으로 확인). 같은 판 다시에 따로 된 키는 없다.
- 모래 모드의 결과 카드도 같은 규칙이다.
- 메뉴로 돌아온 뒤 Enter·Space를 계속 누르고 있어도, 그 자동 반복으로 판이 다시 시작되지 않는다(창이 눌려 있던 키를 메뉴에 넘긴다).

### 4.2 일시정지, 자동 멈춤, 기권

- **P**는 세 모드 모두 멈춤과 계속을 바꾼다. 판의 시계가 하나라 사람 대 AI도 두 쪽이 함께 멈추고 AI도 두지 않는다. 멈춘 동안 화면은 **보드를 가린다**(기록이 남는 판이라 멈춰 놓고 더미를 살펴보는 이득이 없게). 계속하면 2·1 카운트다운(2초) 뒤 다시 간다. 시작 카운트다운 중에 멈췄으면 그 카운트다운을 이어 간다. GO! 글자는 처음에만 뜬다.
- **자동 멈춤:** 창이 포커스를 잃거나 최소화되면 판이 저절로 멈춘다(세 모드). 돌아와도 저절로 가지 않는다(P로 계속). 전체 화면을 바꾸느라 창을 다시 여는 동안은 멈추지 않는다.
- **Esc:** 혼자 연습과 모래 모드는 한 번에 메뉴로 간다. 사람 대 AI는 2초 안에 한 번 더 눌러야 기권하고 메뉴로 간다(멈춘 동안은 한 번). 기권하면 결과 카드 없이 메뉴로 가고, 메뉴가 시작 단추 오른쪽에 2초 동안 알린다: 전적에 패배로 남았으면 '기권 · 패배로 기록했어요', 남지 않았으면(카운트다운 중에 나갔거나 기준 AI 판) '기권했어요'.

### 4.3 기록

- **저장 파일:** 설정과 기록을 파일 하나에 두고, 바꿀 때마다 바로 저장한다. 위치는 Windows `%APPDATA%\TetrisBattle`, macOS `~/Library/Application Support/TetrisBattle`, 그 밖 `~/.config/tetris-battle`이다. `-Dtetris.config=<폴더>`로 바꾸고, `off`면 파일 없이 쓴다. git으로는 가지 않으므로 새 PC는 기본 설정과 빈 기록으로 시작한다.
- **사람 대 AI:** 난이도마다 승·패·무, 가장 빠른 승리, 가장 긴 연승. AI 속도로 나누지 않는다. 카운트다운이 끝난 뒤의 기권은 패다. 카운트다운 중에 나간 판, 오류로 멈춘 판, **기준 AI가 둔 판**(모델을 불러오지 못했거나 판 도중 바뀜)은 남기지 않고, 결과 카드에 '기록 안 함'을 붙인다.
- **혼자 연습:** 설정(블록 속도 + 방해 줄)마다 가장 많이 지운 줄과 가장 오래 버틴 시간. 진 판과 카운트다운 뒤에 그만둔 판을 남긴다.
- **모래 모드:** 최고 점수와 최고 배율. sand-0.3에서 새로 시작한다(10장).
- **새 기록:** 첫 판(첫 승)은 새 기록으로 치지 않는다. 저장할 때 파일을 다시 읽은 기록과 견주므로 다른 창이 그사이 남긴 판도 센다. 결과 카드에 '새 기록'과 둘째 줄('최단 승리 0:41', '3연승', '최장 시간 0:41', '26줄')을 보이고 새 기록 소리를 낸다.
- 메뉴의 사람 대 AI 카드는 시작 단추 왼쪽에 고른 난이도의 전적 한 줄을 보인다(예: '전적 3승 2패 · 1무 · 최고 3연승'. 무승부가 없으면 '· N무'를, 이긴 적이 없으면 연승을 뺀다. 한 판도 없으면 없음).

**사람 판 기록 (승률 예측망 자료, TRAINING 10.9)**

- 사람 판 기록은 게임 실행(`TetrisApp.main`: `gradlew run`, IDE에서 `TetrisApp` 실행)만 켠다. `tetris.records`가 없으면 작업 폴더 기준 `runs/human/data/games/human-<시각>-<시드>.jsonl.gz`에 남긴다.
- `-Dtetris.records=off`로 끈다(대소문자 상관없음, 앞뒤 공백 무시). 빈 값(`-Dtetris.records=`)도 끔이다. 다른 폴더는 `-Dtetris.records=<폴더>`로 준다. 4bbddae와 다른 점: 예전에는 빈 값이 작업 폴더 자체에 기록을 썼고, `' off '`처럼 공백이 있으면 끄지 못했다. 지금은 둘 다 끔이다.
- 새로 받은 저장소(`runs/` 없음)에서도 따로 준비할 것이 없다. 첫 사람 대 AI 판이 끝날 때 `runs/human/data/games` 폴더를 통째로 만든다(`TimedRecorder.writeSingle`). `runs/`는 git에 올리지 않는다.
- IDE에서 게임을 켤 때는 작업 폴더가 저장소 폴더여야 기록이 저장소의 `runs/human`에 모인다. 다른 폴더에서 켜면 `<그 폴더>/runs/human/data/games`에 남는다. VS Code와 `gradlew run`은 기본이 저장소 폴더다.
- 시험·도구·벤치는 사람 판 기록을 남기지 않는다. `GameSession.recordsDir()`는 속성이 없으면 끔이다. Gradle은 시험과 도구 작업에 `-Dtetris.records=off`를 준다. IDE에서 바로 돌린 JUnit은 `src/test/resources/META-INF/services`에 등록한 `TestSandbox`(LauncherSessionListener)가 off로 둔다. 둘 다 없어도 기본값이 끔이다.
- **끝난 사람 대 AI 판만** 남긴다. 혼자 연습, 모래 모드, 기권한 판은 남기지 않는다. 판 도중 기준 AI로 바뀐 판에는 P2 설명에 `fallback_ms`(바뀐 판 시각)를 붙인다.
- 파일은 같은 폴더의 임시 파일(`.<이름>.<수>.part`)에 다 쓰고 디스크에 내린 뒤 이름을 바꿔 끼운다. 판이 끝나자마자 메뉴로 가거나 창을 닫아도 다 쓸 때까지 기다리므로(최대 10초 더) 반쯤 쓴 파일이 남지 않는다. 쓰기에 실패해도 콘솔에 한 줄만 남고 판은 정상으로 끝난다.
- 판 끝 처리 순서: 결과 소리 → 플레이 기록(새 기록과 그 소리) → `runs/human` 승률 자료. 이 일은 게임 진행 스레드가 한 번만 하고, 창은 다시 그리기만 한다.

## 5. AI 조작기 (PLAN 4.3)

AI는 사람과 같은 규칙 안에서 조작한다. 블록마다:

1. **생각:** 블록이 고정되고 새 블록이 나오면 **생각 지연** 동안 아무 입력도 하지 않는다. 지연이 끝나는 틱에 `Brain`이 그 순간의 위치(중력으로 내려왔을 수 있다)에서 내 상태와 상대 상태로 목표 배치를 고른다(학습 대전과 같은 점수 매기기, 온도, 2수 탐색). AI가 계획대로 홀드해서 꺼낸 블록은 같은 계획을 이어 가므로 다시 생각하지 않는다.
2. **실행:** 목표의 **칸 집합과 spin**(정규화 키에서 홀드 표시를 뗀 부분)을 고정한다. 입력 간격(1000 ÷ 초당 입력 ms)마다, 그 순간의 블록 위치에서 배치 탐색(RULES 14장)을 다시 해 목표까지의 경로를 구하고 **첫 조작 하나만** 한다. 목표가 홀드 배치면 첫 조작은 `H`다. 목표에 도착하면(경로가 비면) 하드드롭한다.
3. **재결정:** 중력·락 딜레이 때문에 목표에 갈 수 없게 되면(현재 위치에서 탐색한 결과에 목표가 없으면), 생각 지연 없이 현재 위치에서 다시 고른다. 이미 홀드를 썼으면 홀드 배치는 후보에서 빠진다(GameModel 이 빼 준다).
4. **기록:** 목표를 한 번이라도 바꾼 블록 수 ÷ 블록 수 = **실행 실패율**. 레벨별 5% 이하가 목표다(PLAN 4.3). 헤드리스 가상 시간 시험으로 잰다.

- 고정한 뒤 다음 블록까지의 지연은 생각 지연 하나뿐이다.
- 판이 끝나면 게임 진행 스레드가 끝난 뒤의 처리를 한 번 하고 스스로 끝나며, 미리 고르기 일꾼도 닫는다.

### 5.1 미리 고르기 (`ai.Prefetch`)

- 생각 지연 동안 일꾼 스레드가 미리 고른다. 고를 때 쓰는 것(내 게임 상태, 지금 블록, 상대 상태)을 복사해 일꾼에게 넘긴다.
- 생각이 끝나는 틱에 그 값들이 그대로이고 둘 수 있는 배치의 키도 같으면 미리 고른 답을 쓴다. 하나라도 다르면 버리고 그 자리에서 고른다.
- 온도 0인 두뇌는 같은 입력에 언제나 같은 답을 내므로, 미리 골랐든 아니든 판은 똑같이 흘러간다. 고르기 난수를 쓰는 두뇌(온도 > 0, 1단계 초급)는 미리 고르지 않는다.
- 그래서 2수 탐색(불가능)처럼 무거운 결정도 화면과 판의 시계를 붙잡지 않는다. 실제 시간 측정(`gradlew realtimeBench`, 5단계 40초)에서 미리 고르기는 64번 모두 맞았다.

### 5.2 모델 불러오기와 기준 AI

- **화면 스레드는 모델을 불러오지 않는다.** 게임을 켜면 메뉴 뒤에서 배경 스레드가 모든 난이도·페르소나의 모델과 승률 모델을 미리 불러 둔다(`AiCatalog.preload()`, 6.3). 첫 모델이 약 0.19초(ONNX Runtime 시작), 그 뒤로는 하나에 11~17ms, 모두 합쳐 약 0.47초다.
- 미리 불러오기가 끝나기 전에 판을 시작하면 게임 진행 스레드가 3초 카운트다운 동안 불러온다(보통 0.3초). 다 못 불러오면 카운트다운이 1에서 기다리고("AI 불러오는 중") 판의 시계도 0에 멈춰 있다.
- 메뉴 오른쪽 위에 AI 상태를 짧게 보인다: 'AI 불러오는 중' / 'AI 준비됐어요' / '기준 AI로 대신해요'.
- **기준 AI로 대신할 때** 판 왼쪽 아래 알림:
  - 모델 묶음을 읽지 못함(`-Dtetris.models`를 잘못 줌, `models/`가 없는 곳에서 jar를 켬 등): '학습한 AI를 불러오지 못해 기준 AI로 둬요'.
  - 고른 AI의 모델만 쓸 수 없음: '고른 AI의 모델을 쓸 수 없어 기준 AI로 둬요'.
  - 판 도중 모델이 오류를 냄: 그 틱에 기준 AI로 바뀌어 계속 두고, 'AI 모델에 문제가 생겨 기준 AI로 바꿨어요'와 이름 옆 꼬리표 '기준 AI로 바뀜'을 3초 보인다(판의 시계라 멈춘 동안은 세지 않는다). 그 뒤에는 '기준 AI' 꼬리표가 남는다.
  - 이런 판은 사람 대 AI 전적에 남지 않는다(4.3). 혼자 연습 기록은 그대로 남는다.
- 예상하지 못한 오류는 판을 멈추고 오류 카드를 띄운다(조용히 멈추지 않는다).

### 5.3 AI 속도 (50~150%)

메뉴의 사람 대 AI 카드(‹ 100% ›)와 설정 화면의 AI 속도 갈래에서 고른다. 두 곳은 같은 값이고 바꾸면 바로 저장된다. 10% 단위, 기본 100%다. **결정 품질(모델, 온도, 탐색)과 중력 상한은 바꾸지 않고 조작 속도만** 바꾼다(`AiCatalog.Difficulty.atSpeed`).

```text
T  = 생각 지연 + 6000 / 초당 입력             블록 하나에 드는 시간 (ms, PLAN 7장: 블록당 입력 6회 어림)
T' = T × 100 / AI 속도(%)
생각 지연' = T' − 6000 / 초당 입력             초당 입력은 그대로 (느림은 생각 지연으로 만든다, PLAN 7장)
생각 지연'이 50ms 보다 짧아지면: 생각 지연' = 50ms, 초당 입력' = 6000 / (T' − 50) (원래 값 이상, 많아야 30)
```

- 지금 단계 값에서는 50~150% 안에서 생각 지연이 50ms 밑으로 내려가지 않는다. 그래서 **바뀌는 것은 생각 지연뿐**이다.
- 생각 지연(1~5단계): 50%면 5,600 / 3,300 / 2,000 / 1,095 / 690ms, 100%면 2,200 / 1,150 / 700 / 360 / 225ms, 150%면 1,067 / 433 / 267 / 115 / 70ms.
- 메뉴의 힌트는 고른 난이도의 `T'`다. 예: 중급 100%면 '블록마다 약 2.2초 (기본)', 80%면 '블록마다 약 2.7초 (기본 2.2초)'. 설정의 AI 속도 갈래는 난이도마다 이 시간을 표로 보인다.
- AI 속도가 100%가 아니면 대전 화면의 이름표에 '중급 · AI 속도 80%'처럼 보이고, 사람 판 기록에도 남는다.

**측정** (`gradlew speedBench`, 가상 시간, 양쪽 같은 단계·같은 속도, 그 단계의 중력 상한, 시드 990001~990006, 칸마다 120초까지 6판, 10-07. 원자료 `runs/integration/P1_battle-logic/speed.json`, git 제외)

- '생각하는 동안 굳은 블록'은 AI가 목표를 고르기 전에 중력과 락 딜레이로 고정된 블록이다. **초급 50%만** 생각이 5.6초로 길어, 더미가 약 10줄 넘게 쌓였을 때 블록의 5.6%가 AI가 손대기 전에 떨어져 굳었다. 그 밖은 1.5% 이하다. 바꿀지는 사용자 결정으로 남겼다(블록이 바닥에 닿았고 남은 락 딜레이가 남은 생각 시간보다 짧으면 생각을 일찍 끝내는 방법이 있다).
- 실제 시간 판의 보드 늦음(`gradlew realtimeBench`, 5단계 100%)은 다른 작업이 CPU를 100% 쓰는 동안 중앙 2ms, p95 34ms, 최대 88ms였다. 가벼운 부하에서는 p95 2ms였다. 판 진행 한 틱은 0.1~0.9µs라 늦음은 CPU 경합에서 온다. 150%의 실시간 측정은 아직 하지 않았다. 코어가 적은 느린 PC에서는 5단계가 가끔 0.1~0.3초 멈칫할 수 있다(두는 수와 승패는 같다).

## 6. 난이도와 페르소나

### 6.1 난이도 5단계 `[초안]`

**두뇌는 학습량**으로 나눈다(TRAINING 11.1). 모델은 난이도 사다리(`runs/ladder01`, `runs/ladder02`, 블록 동기 모드 200판)를 보고 골라 `python/tools/make_bundle.py`의 표에 적었다(10-04). 조작 속도와 중력 상한은 PLAN 7장에서 출발해 사용자가 해 보고 두 번 늦췄다(표 아래 메모).

| 단계 | 이름 | 두뇌 (학습량) | 온도 τ | 탐색 | 기준 AI 상대 (블록 동기) | 생각 지연 | 초당 입력 | 중력 상한 | 페르소나 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 초급 | `r01` 세대 0 (학습 전, 기준 평가만) | 0.2 | 1수 | 0.165 | 2,200ms | 5 | 초당 2칸 | 중립만 |
| 2 | 중급 | `r01` 세대 10 | 0 | 1수 | 0.675 | 1,150ms | 6 | 초당 3칸 | 중립만 |
| 3 | 상급 | `r01` 세대 38 | 0 | 1수 | 0.755 | 700ms | 10 | 초당 5칸 | 중립만 |
| 4 | 최상급 | `a2` 세대 52 (`r01` 38세대 + 이어 학습 14세대, β 0.01) | 0 | 1수 | 0.900 | 360ms | 16 | 초당 8칸 | 고름 |
| 5 | 불가능 | `a2` 세대 52 | 0 | 2수(`beam` 8) | 0.985 | 225ms | 25 | 초당 12칸 | 고름 |

- **10-04 사용자 조정.** 해 보니 어렵다고 해서 1~3단계의 조작 속도만 약 20% 늦췄다(생각 지연 900/500/300ms → 1,450/700/400ms, 초당 입력 5/8/12 → 5/6/10). 같은 날 단계 이름을 입문·초급·중급·상급·고수에서 **초급·중급·상급·최상급·불가능**으로 바꿨다(사용자 결정). 메뉴에서 처음 고른 단계는 2단계 중급이다.
- **10-06 사용자 조정.** 다섯 단계 모두 **생각 지연만** 늘렸다(1,450/700/400/180/100ms → 2,200/1,150/700/360/225ms, 52~125% 늘림). 초당 입력, 두뇌, 온도, 중력 상한은 그대로다. 블록 하나에 드는 시간(생각 지연 + 6,000 ÷ 초당 입력)은 26~37% 늘었고, 초당 블록 수로는 21~27% 줄었다(6.4). PLAN 7장대로 느림은 생각 지연으로 만들고 초당 입력은 5 이상으로 둔다. 플레이어가 고르는 AI 속도(5.3)는 이 값 위에 곱한다.
- **온도는 PLAN 7장보다 훨씬 작다.** `Chooser`는 점수를 표준편차로 나눈 뒤 τ로 소프트맥스하므로 τ 0.3만 돼도 학습 전 모델의 승률이 0.04로 떨어진다(τ 0.05 0.465, 0.1 0.42, 0.2 0.165, 0.5 0.005, 1.0 0). PLAN 7장의 1.0 / 0.7 / 0.4 / 0.2는 쓰지 않는다.
- 메뉴의 한 줄 설명: 초급 '처음 해 보는 분께 알맞은 느긋한 AI', 중급 '기본기를 익히는 단계', 상급 '꾸준히 줄을 지우는 AI', 최상급 '빠르고 정확한 AI', 불가능 '다음 블록까지 내다보는 가장 강한 AI'. 강도 막대의 이름은 'AI 실력'이다.
- 사람이 느끼는 난이도는 조작 속도(초당 블록 수)가 가장 크게 정한다(PLAN 7장). 가상 시간 모드로 잰 단계별 실행 실패율·초당 블록 수·이웃 단계 승률은 6.4.

### 6.2 페르소나

- 페르소나는 **학습 방향**(스타일 보상)이 다른 모델이다(TRAINING 9장). 메뉴에서 `중립`(난이도 사다리의 모델)과, 페르소나 학습으로 만든 게임용 파일 넷 중에서 고른다.
- 페르소나를 고르면 **두뇌만** 그 페르소나 모델로 바꾸고, 온도·탐색·조작 속도·AI 속도·중력 상한은 고른 난이도를 따른다.
- **페르소나는 4·5단계(최상급·불가능)에서만 고른다**(10-04 사용자 결정, 모델 묶음의 난이도마다 `"personas": true/false`). 그 아래 단계에서는 메뉴의 페르소나 줄이 잠기고 중립을 쓴다. 그래서 "난이도 = 학습량"이 그대로 지켜진다. 메뉴의 안내 문구("페르소나는 최상급·불가능에서 고를 수 있어요")도 이 값에서 단계 이름을 가져온다.
- **지금 묶음의 페르소나 (10-11): 중립 + 페르소나 다시 학습 `p05a` 세대 30의 원형마다 첫 AI 넷.** 설계와 고른 과정은 TRAINING 9.10. 10-04~10-11에는 `p04` 세대 10을 썼다(TRAINING 9.9, 파일은 `weights/p04`에 남아 있다).

| 페르소나 | 메뉴 설명 | 배운 보상 (TRAINING 9.10) | 4단계 중립 상대 승률, 실시간 (± 95%) | 실시간에서 본 행동 (p05 중립 대비) |
|---|---|---|---|---|
| 중립 | 이기는 것만 배운 기본 AI | 승패만 | (4단계 두뇌 그 자체) | — |
| 공격형 | 한 번에 여러 줄을 지우도록 배운 AI | 공격, 테트리스 +, 싱글 − | 0.605 ± 0.048 | 싱글 −13.4%, 한 번에 지운 줄 +6.4%, 테트리스 +10.2%(p 0.12) |
| 수비형 | 보드를 낮고 깔끔하게 지키도록 배운 AI | 높이·구멍·위험·방해 줄 비용 | 0.590 ± 0.048 | 최고 높이 −5.0%, 구멍 −7.1%, 위험 −11.4%, 판 길이 +8.3% |
| T-spin형 | T-spin을 노리도록 배운 AI | T-spin 클리어 | 0.568 ± 0.049 | T-spin +263%(나머지 원형의 3.70배) |
| 콤보형 | 연속 클리어를 길게 이어 가도록 배운 AI | 콤보 클리어, 콤보 길이 | 0.575 ± 0.048 | 콤보 길이 +8.4%, 콤보 비율 +7.9%, APP +2.1% |

- **실시간 측정** (`runs/p05-bundle/bench/level4.json`, git 제외): 가상 시간 모드, 양쪽 모두 4단계 설정(생각 360ms, 초당 입력 16, 중력 상한 같음), 상대는 4단계 중립(`a2` 세대 52), 시드 990001~990200 × 자리 2 = 페르소나마다 400판. 실행 실패율 5.7 × 10⁻⁵ 이하, 시간 초과 0, 오류 0. 같은 측정에서 `p04` 세대 10은 0.480 / 0.508 / 0.523 / 0.493이었다.
- **p05 페르소나는 4단계 두뇌보다 조금 강하다**(0.568~0.605). 학습을 30세대 더 한 몫으로 보인다(같은 실행의 중립 대조도 0.568). 그래서 최상급에서 페르소나를 고르면 중립보다 승률이 약 0.07~0.10 높은 AI를 만난다. 4단계 페르소나와 5단계 중립 사이는 재지 않았다.
- **미리 정한 행동 기준**(TRAINING 9.10)을 넘은 것은 **T-spin형·콤보형**이다. 공격형·수비형은 방향은 설계와 같고 통계로도 뚜렷하지만(p < 0.01) 미리 정한 문턱에는 못 미쳤다. 메뉴 문구는 학습 방향만 말하므로 그대로 둔다.
- 승률 막대(`wp02` + 보정층)는 `p04` 페르소나가 섞인 실시간 자료로 학습했고 다시 학습하지 않았다. `p05` 페르소나 판에서 보정이 얼마나 맞는지는 아직 재지 않았다.
- **메뉴는 가볍게** (10-04 사용자 결정): 난이도는 짧은 한 줄과 강도 막대, 페르소나는 무엇을 하도록 배웠는지 한 줄만 보인다. 학습 세대, 생각 지연·초당 입력 같은 자세한 정보와 시험 결과는 문서(TRAINING 9.9·9.10·11.1, 이 문서 6.1)에만 둔다.

### 6.3 모델 묶음 `models/manifest.json`

게임은 저장소의 `models/` 폴더(다른 폴더는 `-Dtetris.models=<폴더>`)에서 모델을 찾는다. 파일이 없거나 꼬리표(`tetris.model_io`, `tetris.rules`)가 맞지 않거나 ONNX Runtime이 없는 PC면 **기준 AI(`BaselineScorer`)로 대신**하고 메뉴와 판에 표시한다(5.2).

```json
{
  "format": "models-1",
  "difficulties": [
    {"id": 1, "name": "초급", "model": "value_r01-g000.onnx", "temperature": 0.2, "beam": 0,
     "think_ms": 2200, "inputs_per_sec": 5, "gravity_cap": 2,
     "description": "처음 해 보는 분께 알맞은 느긋한 AI", "personas": false},
    ...
  ],
  "personas": [
    {"id": "neutral", "name": "중립", "model": null, "description": "이기는 것만 배운 기본 AI"},
    {"id": "attacker", "name": "공격형", "model": "value_attacker.onnx",
     "description": "한 번에 여러 줄을 지우도록 배운 AI", "source": "runs/p05a/models/value_attacker_gen-030.onnx"},
    ...
  ],
  "winprob": "winprob.onnx"
}
```

- `model`은 `models/` 기준 경로, `"baseline"`이면 기준 AI다. 중립 페르소나(`model: null`)는 난이도의 모델을 쓴다.
- `gravity_cap`은 RULES 6.3 표의 단계 번호가 아니라 **초당 칸 수**다. 그 값을 넘지 않는 가장 높은 단계까지 올라간다.
- 승률 모델 옆의 `winprob_calibration.json`(보정층, TRAINING 10.12)은 그 `model_sha256`이 `winprob.onnx`와 같을 때만 붙는다. 승률 막대는 이 보정한 값을 쓰고, 판 시작 막대는 정확히 0.5다.
- **미리 불러오기:** 게임을 켜면 배경 스레드(`model-preload`)가 `AiCatalog.preload()`로 모든 난이도와, 페르소나를 고를 수 있는 단계의 페르소나 모델, 승률 모델을 한 번씩 불러 둔다. 쓸 수 없는 모델이 있으면 메뉴 상태에 보인다. 이미 불러 본 모델로 고르는 것은 잠금 없이 바로 한다.
- **연산 스레드:** 모델 하나가 쓰는 ONNX 연산 스레드 수는 `AiCatalog.GAME_THREADS` = 논리 코어의 절반, 많아야 4다. 불가능 단계의 2수 탐색 같은 큰 묶음이 약 2.2배 빨라지고(10-04 측정, 4,000개 묶음 96ms → 43ms), 점수는 스레드 수와 상관없이 비트 단위로 같다.
- **`models/`는 git에 넣는다** (10-04 사용자 결정). 팀원이 저장소를 받자마자 학습한 AI로 게임할 수 있다. 묶음은 `python/tools/make_bundle.py --p05-personas`가 `runs/`에서 복사해 만든다(10-11). 가치망 4개 약 2.8MB + 페르소나 4개 약 2.8MB(2,850,562바이트) + 승률 모델 0.85MB + 보정층, 모두 11개 파일 약 6.5MB다. `--p04-personas`는 10-04~10-11의 묶음을 바이트까지 다시 만든다. `runs/p04/personas/`의 자동 이름 파일은 이름이 설계와 맞지 않아 쓰지 않는다(TRAINING 9.9).

### 6.4 가상 시간 모드 측정 (10-06, `gradlew levelBench`)

`models/`의 다섯 단계를 가상 시간 모드(RULES 12.3)로 대전시켰다. 같은 단계끼리 40판(그 단계의 중력 상한), 이웃한 단계끼리 40판(시드마다 자리를 바꿔 두 판, 위 단계의 중력 상한). 시드는 `950001`부터. 10-06에 생각 지연을 늘린 뒤(6.1) 같은 시드로 다시 쟀다. 결과는 `runs/levels04/levels.json`이다. 괄호 안은 10-04 저녁(`runs/levels03`, 1~3단계만 늦춘 뒤)과 10-04 낮(`runs/levels01`, 늦추기 전)의 값이다.

| 단계 | 실행 실패율 (목표 5% 이하) | 초당 블록 수 (10-04 저녁 / 10-04 낮) | PLAN 7장 어림 | 같은 단계끼리 평균 판 길이 | 바로 아래 단계 상대 승률 |
|---|---|---|---|---|---|
| 1 초급 | 0% | **0.31** (0.39 / 0.50) | 0.29 | 144초 | |
| 2 중급 | 0% | **0.48** (0.61 / 0.79) | 0.47 | 174초 | 1.000, 40승 0패 |
| 3 상급 | 0.013% | **0.76** (0.97 / 1.18) | 0.77 | 126초 | 0.975, 39승 1패 |
| 4 최상급 | 0% | **1.30** (1.69 / 1.69) | 1.36 | 96초 | 1.000, 40승 0패 |
| 5 불가능 | 0% | **2.02** (2.66 / 2.66) | 2.15 | 206초 | 0.975, 39승 1패 |

- **실행 실패율은 모든 단계에서 목표보다 훨씬 낮다.** 생각 지연 동안 블록이 내려와도, 중력 상한이 낮은 단계는 목표 자리에 가기에 시간이 넉넉하다.
- **초당 블록 수는 늘린 생각 지연만큼(21~27%) 줄었다.** PLAN 7장의 어림(1 ÷ (생각 지연 + 6 ÷ 초당 입력), 블록당 입력 6회)과 거의 같다. 4·5단계가 어림보다 조금 느린 것은 실제 경로가 6회보다 조금 길기 때문이다.
- **위 단계가 바로 아래 단계를 거의 언제나 이긴다(0.975~1.0).** 블록 동기 모드의 두뇌 차이(TRAINING 11.1)에 조작 속도 차이가 더해졌기 때문이다. 사람이 느끼는 단계 차이도 주로 속도에서 온다.
- 이 측정은 AI끼리의 결과다. 사람 상대 승률(PLAN 7장 목표 90 / 70 / 50 / 30 / 10%)은 사람이 직접 해 봐야 안다.

- **바닥에 닿은 블록**은 고정까지 남은 시간만큼 어두워지고, 리셋이 13번을 넘으면 테두리가 깜빡인다.
- **동작 글자:** 보드 옆에 'T-SPIN', 'DOUBLE', 'B2B ×2', '3 COMBO', '2줄 → 공격 6', 공격 내역('기본 2 + 콤보 1'), 상쇄('상쇄 1 · 보냄 2'). 튀어나왔다가 천천히 옅어진다. 퍼펙트 클리어는 보드 가운데 금색 띠로.
- **공격 표시**(과제 3번): 보낸 공격이 '+N' 칩으로 상대의 받을 방해 줄 막대까지 0.45초 동안 날아가고, 도착한 칸들이 반짝인다.
- **효과:** 줄 지우기는 흰 띠 번쩍임(1초에 3번까지), 양쪽 벽 불꽃, 칸 색 조각. 4줄·T-spin·퍼펙트 클리어는 보드 테두리 빛이 잠깐 커지고, 퍼펙트 클리어에는 금빛 고리와 조각이 더해진다. 블록을 놓으면 놓인 칸이 잠깐 하얗게 빛난다. 하드드롭은 떨어진 길에 꼬리가 남고(블록이 내려앉은 자리 기준, 칸이 모두 지워진 테트리스에도 나온다) 보드가 2~4화소 툭 튄다. 큰 충격에는 사람 보드만 흔들린다. AI 보드는 효과를 절반만 쓰고 흔들리지 않는다.
- 효과 세기·화면 흔들림·번쩍임 줄이기·고스트·색약 색상·블록 무늬는 판을 시작할 때의 설정을 따른다(7.4).
- **예측 승률**(과제 2번): 막대 13칸 폭, 50% 눈금, 양 끝에 큰 '나 34%' / '66% AI'. 블록이 고정될 때마다 보정한 승률 `WinRate.p1Win(상태, 상태, 판 시간)`(TRAINING 10.12)으로 다시 재고, 값은 컴퓨터 속도와 상관없이 같은 빠르기로 부드럽게 따라간다. 원인이 있는 5%p 이상의 움직임에만 원인 칩('AI 공격 3줄', '나 방해 줄 2줄 올라옴', '나 1줄 지움')을 1.6초 띄운다. 아래에는 판 동안의 흐름. 승률 모델이 없으면 숨기고, 혼자 연습에는 없다. 예측이 한 번 실패하면 그 판에서는 막대만 숨기고 판은 계속한다.
- **시작 카운트다운:** 3·2·1은 숫자마다 색이 다르고 튀어나오며 메아리를 남긴 뒤 GO!. 화면은 25%만 어둡게 해서 판이 보인다. 모델을 불러오느라 늦어지면 'AI 불러오는 중'.
- **K.O.:** 진 보드가 아래 줄부터 회색으로 바뀌고, 흰 번쩍임과 테두리 물결 뒤에 기울어진 빨간 'K.O.' 도장이 찍힌다. 이긴 보드에는 금빛이 두 번 맥박치고 이름 옆에 'WIN'.
- **일시정지 카드**와 **기권 확인 알림**은 부드럽게 나타나고 사라진다. 멈춘 동안은 보드를 가린다(4.2).
- **다시 그리기:** 15ms 타이머는 화면에 보이는 동안만 돈다. 결과 카드, 일시정지, 오류 카드처럼 멈춘 그림은 다 나타난 뒤 더 다시 그리지 않는다.

### 7.3 결과 카드

- 위에서부터 제목(승/패/무), 메타 줄('끝난 이유 · m:ss · 시드 N'), 큰 숫자 '나 47 : 49 AI'(공격).
- **끝난 이유:** 블록 아웃·락 아웃은 '꼭대기까지 쌓임', 가비지 아웃은 '방해 줄에 밀려 넘침'. AI가 졌으면 'AI가 꼭대기까지 쌓임'처럼 쓰고, 둘 다 끝나면 '동시에 끝남'. 기준 AI가 둔 사람 대 AI 판은 메타 줄 끝에 '기록 안 함'.
- **표:** PPS, APP, 지운 줄, 보냄, 받은 줄, 최대 콤보, T-SPIN, 테트리스. 숫자는 0부터 세어 올라간다. 사람 대 AI의 비교 막대는 숫자 아래의 얇은 띠이고, 나은 쪽은 띠가 진하고 숫자가 그 사람의 색이다(숫자 대비 5.5~7.8:1). '받은 줄'은 막대 없이 숫자 색만 쓴다.
- 새 기록이면 금색 '새 기록' 꼬리표와 둘째 줄(4.3). 아래에는 예측 승률 흐름 그래프(긴 판은 점을 솎아 그린다).
- 단추와 키는 4.1. 기권하면 결과 카드 없이 바로 메뉴로 간다(4.2). 기권 카드(이유 '기권')는 화면 확인 도구와 시험에서만 보인다.

### 7.4 설정 화면 (6갈래)

메뉴 오른쪽 위 '설정'으로 연다. 위쪽 카드로 갈래를 고르고, 바꿀 때마다 바로 저장한다. 파일에 남지 않는 실행이면(`-Dtetris.config=off`, 새 버전의 파일, 읽기·저장 실패) 제목 아래 줄이 '이번 실행 동안만 바뀌어요'다. 키보드는 ↑↓←→(옮기기·값 바꾸기), Tab·Shift+Tab, Enter·Space(고르기), Esc(메뉴로)만 쓴다.

| 갈래 | 내용 | 기본값 |
|---|---|---|
| 조작 | 블록 조작 7줄과 화면 조작 4줄(일시정지, 메뉴·기권, 다시 하기, 전체 화면). 칸을 고르고 Enter → 새 키를 누른다. 다른 동작이 쓰던 키면 맞바꾸고 '하드드롭 키는 이제 C' 같은 알림과 함께 그 줄이 반짝인다. 쓸 수 없는 키는 이유 한 줄('한/영 키는 쓸 수 없어요'), Esc는 기다림 취소. Delete·Backspace(또는 ×)로 키 빼기, 줄 끝 ↺로 그 동작만 기본 키로, '키 모두 기본값으로'(두 번 누름) | 4장의 기본 키 |
| 감도 | DAS·ARR 막대(기본값 눈금), 누르고 있을 때 블록이 언제 움직이는지 보여 주는 시간 줄 | DAS 170ms, ARR 50ms |
| 화면 | 고스트, 색약 색상(색약이 있어도 잘 구분되는 색 묶음), 블록 무늬(색 없이도 구분), 전체 화면으로 시작. 오른쪽에 미리 보기 | 고스트 켬, 나머지 끔 |
| 효과 | 효과 세기(끔·약하게·보통·강하게 = 0 / 0.5 / 1 / 1.5배), 화면 흔들림(큰 줄 지우기·큰 공격·하드드롭 때 보드가 흔들림), 번쩍임 줄이기. 오른쪽에 줄을 지우는 작은 판이 지금 설정대로 움직인다 | 보통, 흔들림 켬, 번쩍임 줄이기 끔 |
| 소리 | 효과음 크기(바꾸면 그 크기로 작은 소리를 들려준다), 음소거, 소리 들어 보기, 심장 소리. 소리가 나지 않으면 그 까닭('실행 옵션으로 소리를 꺼 두었어요', '소리 장치를 찾지 못했어요' …) | 70%, 음소거 끔, 심장 소리 켬 |
| AI 속도 | 사람 대 AI의 AI 속도(50~150%, 메뉴와 같은 값)와 난이도마다 블록 하나에 드는 시간 표 | 100% |

- 기본값을 가리키는 말은 모두 '기본'이다('모두 기본값으로', '키 모두 기본값으로', '기본 키로', '100%가 기본 속도예요').
- 효과·화면·키 설정은 세 모드에 모두 적용된다. 판은 시작할 때의 설정으로 둔다.

### 7.6 창과 화면 바꾸기

- **메뉴 ↔ 판:** 120ms 동안 어두워졌다가 250ms 동안 밝아진다. 메뉴에서 판으로 갈 때는 살아 있는 메뉴 위에 검은 막만 칠한다. 판을 떠날 때는 판을 바로 멈추고(기권·기록) 멈춘 그림을 떠서 어둡게 한다. 어두워지는 동안에는 키·마우스를 막아 판이 두 번 시작되지 않는다. 결과 카드의 '다시 하기'·'같은 판 다시'는 어두워지지 않고 바로 바꾼다.
- 설정·도움말은 메뉴 오른쪽 위 단추로 바로 오간다(열 때 고르기 소리, 돌아올 때 뒤로 소리).
- 판을 떠날 때는 창이 판을 먼저 멈춘 뒤(그 뒤로 그 판은 소리를 내지 않는다) 울리던 소리를 끄고 메뉴 소리를 낸다. 그래서 늦춘 방해 줄 경고나 심장 소리가 메뉴 위에서 울리지 않는다.
- 앱 아이콘은 코드로 그린다. 창 이름은 'Tetris Battle'이다.
- **시작:** Windows에서는 깨지 않고 잠자는 데몬 스레드(`timer-resolution`)로 타이머 간격을 1ms로 둔다. 기본 15.6ms로는 메뉴·설정의 33ms 타이머가 47ms(21fps)로 돈다. 글꼴 넷은 배경 스레드(`font-preload`)가 먼저 읽는다. 설정 파일의 경고(저장 실패 까닭 등)는 표준 오류에 '설정 파일: …'로 한 번씩 남긴다.
- **ONNX Runtime DLL:** Gradle의 `run`·시험·도구는 `build/onnxruntime-native`에 한 번 푼 DLL을 넘긴다. Gradle 밖에서(IDE에서 바로) 켜면 DLL 셋을 `%LOCALAPPDATA%\TetrisBattle\onnxruntime-<jar 버전>`에 한 번 풀어 두고 다시 쓴다. 그래서 실행마다 `%TEMP%`에 16MB씩 쌓이지 않는다(Windows x64).
- **그리기 비용:** 둥근 카드는 미리 그려 둔 9조각 그림으로 붙이고(`ThemeCard`), 메뉴의 움직이지 않는 부분은 바뀔 때만 그림 한 장에 다시 그린다. D3D 화면 밖 그림으로 잰 프레임 시간(1920 × 1080, 중앙값, 고치기 전 → 뒤)은 메뉴 6.45 → 1.11ms, 설정 효과 갈래 5.51 → 1.51ms, 도움말 5.60 → 2.32ms, 대전 5.34 → 2.68ms다(10-11).

## 8. 소리

효과음은 대부분 코드로 합성하고(`audio.SoundBank`), 합성으로는 잘 안 되는 몇 가지만 함께 배포하는 **CC0 녹음 13개**(Kenney, `src/main/resources/sfx/`)를 쓰거나 합성음에 겹친다. 외부 라이브러리 없이 JDK의 `javax.sound.sampled`만 쓰고, 자기 스레드의 작은 믹서로 섞어 낸다. 테트리스 공식 음악(Korobeiniki)은 쓰지 않는다.

- **녹음을 쓰는 소리:** 메뉴 이동·고르기·뒤로·안 됨, 블록이 바닥에 닿음, 고정, 하드드롭(합성음과 겹침), 모래 부서짐(겹침), K.O.(겹침). 출처는 그 폴더의 `README.txt`와 `CREDITS.md`.
- **합성음:** 이동, 회전, 홀드(실패하면 '안 됨'), 줄 지우기 1~4(테트리스는 따로 만든 소리), T-spin(미니는 전용 소리), 콤보(12단계까지 음이 올라감), B2B(연속 1~3, 4~7, 8 이상의 세 단계), 퍼펙트 클리어, 상쇄, 방해 줄 경고와 상승, 속도 단계 오름, 위험 심장 소리, 3·2·1·GO, 일시정지·계속, 승리·패배 음악, 새 기록, 모래 지우기·연쇄.
- 하드드롭은 떨어진 거리(2칸 이하 / 3~9칸 / 10칸 이상)에 따라 세 단계로 커진다. 모든 소리를 귀에 들리는 크기 기준 하나로 맞췄다(테트리스 0, 퍼펙트 클리어 +2, 자주 나는 이동 −20). 큰 사건 때는 다른 소리를 잠깐 줄인다.
- **누구의 소리인가:** 조작·고정·줄 지우기 소리는 사람의 블록에만 낸다. AI의 조작과 줄 지우기는 소리가 없다. AI의 공격이 나에게 오면 공격 칩이 닿는 0.45초 뒤 방해 줄 경고가 울린다.
- **판 끝:** K.O.가 바로 나고, 0.65초 뒤 승리나 패배 음악, 새 기록이면 새 기록 소리를 더한다. 기권한 판과 오류로 멈춘 판은 결과 소리가 없다. 카운트다운, 일시정지·계속, 심장 소리, 메뉴 소리는 화면이 낸다.
- **실행 옵션:** `-Dtetris.sfx=synth`면 녹음을 하나도 쓰지 않고 모든 소리를 합성한다(예전 소리와 견줄 때). `-Dtetris.sound=off`면 소리를 끈다. 소리 장치가 없거나 창 없이 실행해도 소리는 꺼지고, 설정의 소리 갈래가 그 까닭을 알린다. PowerShell에서는 `-D…`를 따옴표로 감싼다.
- 녹음 파일을 읽지 못하면 그 소리만 합성음으로 대신하고, 녹음 이름마다 한 번 표준 오류에 '효과음 녹음을 읽지 못해 합성음으로 대신함: <이름> (<까닭>)'을 남긴다(`-Dtetris.sfx=synth`로 일부러 끈 것은 남기지 않는다).
- 들어 보기: `gradlew soundPreview`가 모든 소리를 `build/sfx-preview`에 WAV로 쓰고 크기를 표로 찍는다(`--args="play"`면 차례로 들려준다).

## 9. 글꼴, 그림, 출처

- **글꼴:** Pretendard 1.3.9(한글과 보통 글자, Regular·Bold)와 Barlow Condensed 1.408(숫자와 큰 글자, Bold·Black)을 원본 그대로 `src/main/resources/fonts/`에 넣었다. 둘 다 SIL Open Font License 1.1이고 라이선스 파일이 같은 폴더에 있다. 게임이 jar 안의 파일을 직접 읽으므로 PC에 깔린 글꼴과 상관없이 같은 모양이다. 못 읽으면 예전 '맑은 고딕'으로 그리고 까닭을 한 줄 남긴다.
- 글자는 큰 글자·제목·본문·작은 라벨·숫자 다섯 역할로 나누고, 숫자는 폭을 고정해 시계나 점수가 바뀌어도 옆으로 흔들리지 않는다. Barlow에 없는 글자(한글, 화살표)는 Pretendard로 그린다. 작은 라벨 색의 대비는 5.18:1이다(작은 글자 기준 4.5:1 이상).
- **그림:** 블록, 카드, 효과, 앱 아이콘은 모두 코드(Java2D)로 그린다. 다른 게임의 그림·스크린샷은 저장소에 넣지 않았다.
- **출처:** 함께 배포하는 바깥 파일은 글꼴 두 가지와 효과음 13개뿐이다. 출처, 라이선스, 참고만 한 게임과 지침, 상표 안내는 저장소 맨 위의 [CREDITS.md](../CREDITS.md)에 있다. 도움말 맨 아래에도 한 줄로 보인다.

## 10. 모래 모드 (`sand-0.3`, 10-11)

모래 모드는 혼자 하는 끝없는 판이다. 원작은 Sandtrix이고, 조작과 블록 규칙은 우리 게임 것(SRS 킥, 7-bag, 홀드, 미리보기 5개, 하드드롭, 소프트드롭, 고스트, 락 딜레이 500ms·리셋 15회)을 그대로 쓴다. 고전 규칙(core, RULES 0.3), 픽스처, 학습 모델은 건드리지 않는다. 규칙 전체는 `sand` 패키지 설명(package-info)에, 수치는 `SandRules`에 있다. 여기에는 무엇을 하면 지워지고 언제 지는지를 적는다.

- **판:** 칸으로는 고전과 같은 10 × 24이고, 칸 하나가 8 × 8 알갱이 `[초안]`라서 80 × 192 알갱이다. 색은 빨강·파랑·초록·노랑 넷이다. 블록 색은 12개 색 가방에서 따로 뽑아 미리보기와 홀드에도 보인다.
- **흐름:** 블록이 고정되면 같은 색 알갱이 256개로 부서진다. 모래는 아래로, 막히면 아래 대각선으로 흐른다. 대각선으로 가려면 대각선 칸의 바로 아래 칸까지 비어야 해서(sand-0.2부터) 쌓인 모래가 약 63°로 선다. 받침이 흘러가 버린 블록은 공중에서 고정되지 않고 다시 떨어진다.
- **점수와 단계:** 점수 = 지운 알갱이 수 × 콤보 배율. 1.5초 `[초안]` 안에 다시 지우면 배율이 한 단계 올라 ×10까지 간다. 고른 시작 단계에서 30초마다 한 단계 올라 10에서 멈춘다(중력은 RULES 6.3 표).
- **지우기:** 같은 색 모래 덩어리(대각선까지 8방향으로 이어짐)가 왼쪽 벽과 오른쪽 벽을 함께 잇고, 알갱이가 **640개 이상**(칸 한 줄 분량, 판 너비로 펴면 평균 한 칸 두께)이면 0.2초 반짝인 뒤 사라진다. 사라진 자리로 위의 모래가 떨어지며 새 덩어리가 이어지면 다시 지워진다(연쇄). 메뉴·도움말·판 옆 목표 카드는 "같은 색 모래로 양쪽 벽을 두툼하게 이으면 사라져요"라고 쓴다.
- **얇은 띠:** 양쪽 벽을 이었지만 640개가 안 되는 덩어리는 지워지지 않고 남는다. 화면은 그 덩어리를 옅게 밝히고(빛 물결이 왼쪽 벽에서 오른쪽 벽으로 흐른다), 판 바깥 양쪽의 닿은 자리에 띠 색 삼각형을 두고, 목표 카드의 "두툼하게"를 모래색으로 바꾼다. 0.15초 넘게 남은 띠만 보인다(모래가 흐르며 잠깐 이어졌다 끊기는 띠는 보이지 않는다). 효과를 끄거나 번쩍임 줄이기를 켜면 물결 없이 고르게 밝힌다. 색약 색상에서도 보인다.
- **패배:** 정착한 모래가 점선(스폰 여백) 위에 있으면 진다. 다음 블록의 스폰 자리를 흐르는 모래가 막으면 비켜날 때까지 기다리고, 막은 모래가 그대로 멈추면 진다. 0.6초 넘게 기다리면 넘침 선 아래에 '모래가 비켜나면 나와요' 꼬리표가 나온다.
- **바꾼 까닭 (sand-0.2 → 0.3):** sand-0.2 에서는 아무것도 누르지 않아도 지지 않았다. 블록이 모두 가운데에 떨어져 더미가 생기고, 새 블록 하나(256알)가 더미 비탈을 얇게 덮으며 혼자 양쪽 벽을 이어 지워졌기 때문이다. 아무것도 누르지 않는 판이 24판 모두 10분을 버텼고 점수(중앙 158,993)가 사람처럼 두는 손(2.3만~6.8만)보다 높았다. (그 전의 sand-0.1은 모래가 45°로 흘러 하드드롭만 해도 지지 않았고, 10-07의 sand-0.2가 경사를 가파르게 했다.)
- **최고 점수:** 규칙이 바뀌어 모래 최고 점수는 sand-0.3 에서 새로 시작한다. 저장 파일의 모래 기록에 규칙 세대(`record.sand.rules=3`, `PlayRecords.SAND_RULES`)를 함께 적고, 세대가 없거나 다른 옛 모래 기록은 읽을 때 버린다(경고는 콘솔에만). 다른 기록과 설정은 그대로 읽는다.
- **화면:** 판 옆에 목표 카드 세 줄('같은 색 모래로 양쪽 벽을 두툼하게 이으면 사라져요', '연달아 지우면 배율이 올라요', '점선 위까지 쌓이면 끝나요'), 점수, 배율, 단계, 홀드, 미리보기. 지워질 모래는 한 번 밝아졌다 가라앉고, 사라질 때 조각이 튀며 '+점수'(배율 2 이상이면 '×N')가 떠오른다. 결과 카드의 메타 줄은 '점선 위까지 쌓임 · 최고 N · m:ss.mmm'이고 키는 4.1과 같다. 설정(키, DAS·ARR, 고스트, 색약 색상·블록 무늬, 효과)은 모래 화면에도 그대로 적용된다.
- **모래 AI**(`sand/ai`)는 게임에 붙이지 않는다. 화면 확인 도구(`sandScreens`, `sandSoak`)와 시험·벤치에서 손 대신 쓴다. 모래 판은 사람 판 기록(`runs/human`)에 남기지 않는다.

## 11. 시험

| 대상 | 시험 |
|---|---|
| `TimedPlayer` | 중력 누적(초당 1칸이면 1000틱째 한 칸), 바닥 닿으면 `acc = 0`, 락 딜레이 500틱째 고정, 리셋 15회와 15번째 리셋, 최저 행 갱신으로 리셋 횟수 0, 떨어졌다 다시 닿을 때 타이머, 실패한 조작이 타이머를 안 바꿈, 홀드 한 번만, 하드드롭 즉시 고정, 회전으로 끼우고 하드드롭한 T-spin |
| `GameModel` 실시간 확장 | `lock(PieceState)`와 `apply(Placement)`가 같은 배치에 같은 결과, 홀드 후 `placements()`에 홀드 배치 없음, 블록 도중 상태에서의 배치 탐색 |
| `TimedMatch` | 틱 끝 송신, 같은 틱 둘 다 패배 → 무승부, 중력 단계와 상한, 같은 시드·입력이면 같은 결과 |
| `AiController`, `Prefetch` | 중력 0에서 목표 배치를 그대로 둠(블록 동기 모드와 같은 배치 열), 생각 지연과 입력 간격 지킴, 빠른 중력에서 재결정, 홀드 배치 실행, 실행 실패율 측정, 미리 골라도 판이 같음 |
| `Brain` | 학습 대전 기록이 바뀌지 않음(`fixtures/match` 재생, `MatchRunnerTest`) |
| `HumanInput`, `KeyTracker`, `KeyBindings` | 누를 때 한 번, DAS 뒤 ARR 마다 반복, 양쪽을 누르면 나중 쪽, 한 번 하는 조작은 빠짐없이 한 틱에 하나, 포커스를 잃으면 모두 뗌, 자동 반복 무시, 키 맞바꾸기와 쓸 수 없는 키 |

| `WinRate`, `WinCalibration` | Java = Python 보정 식과 실제 상태 120쌍(TRAINING 10.12), 판 시작 막대 0.5 |
| `GameSession` | 소리(AI 는 조용함, 결과 소리 한 번), 보정한 승률 막대, 카운트다운 동안 모델 불러오기, 같은 판 다시, 사람 판 기록(원자적 쓰기, 기본 끔, 게임 실행만 켬), 기록 규칙 |
| `settings` | 저장 파일(옛 파일 읽기, 망가진 파일, 원자적 저장), 설정 기본값과 범위, 전적과 새 기록, 모래 기록 규칙 세대 |
| `audio` | 소리 사건 표, 쿨다운, 크기 맞춤, 녹음 13개 읽기와 실패 알림, 부드러운 닫기 |
| `sand`, `sand/ai` | 흐름(63°), 640알 문턱(639알은 남고 640알은 지움), 얇은 띠, 무입력 판이 5분 안에 짐(시드 990001~3: 162·196·164초), 패배와 스폰 기다림, 결정론 |
| 화면 | 메뉴·설정·도움말·대전·모래 화면의 키와 그림(같은 판이면 같은 그림), 결과 카드 키, 일시정지가 보드를 가림. 배치는 `gradlew screenshot`·`screensPreview`·`sandScreens`(창 없이 그린 그림)로 확인. 키 감각과 체감 난이도는 사람이 직접 해 봐야 한다 |

- **개수 (10-11):** Java 시험 812개(공통 픽스처 `FixtureTest` 103개 포함, 4bbddae 때 749개). Python 시험 117개. `gradlew build`가 Java 시험을 모두 돌린다.
- 모든 JUnit 실행(`gradlew test`, VS Code, IntelliJ)은 창 없이 돌고, 진짜 소리 장치, 사용자 설정 폴더, `runs/human`을 건드리지 않는다(Gradle의 시험 설정과 `TestSandbox`).
- 모래 실시간 시험(`SandSessionTest`)은 CPU가 아주 바쁘면 가끔 실패할 수 있다. 게임 동작과는 관계없다.
