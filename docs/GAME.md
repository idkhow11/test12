# 게임 설계 (2인 대전 화면, 실시간 조작, AI 조작기)

> 2026-10-04 시작. 10-04에 범위가 "게임 전체도 개발"로 바뀌었다(PROGRESS 0.2). 규칙의 기준은 [RULES.md](RULES.md), AI의 배치 고르기와 모델은 [TRAINING.md](TRAINING.md), 모델 입출력은 [MODEL_IO.md](MODEL_IO.md)다. 이 문서는 그 위에 얹는 **게임**(화면, 입력, 실제 시간 진행, AI가 사람처럼 조작하기, 난이도·페르소나 고르기)을 정한다. `[초안]`은 플레이 테스트로 바꿀 값이다.

## 1. 첫 판의 범위

| 들어감 | 들어가지 않음 |
|---|---|
| **사람 대 AI** (난이도 5단계 × 페르소나), **혼자 연습** | AI끼리 관전, 2인 키보드 대전, 네트워크, 과제 7·9·10번 |
| 2인 보드 화면, 고스트, 미리보기 5개, 홀드, 받을 가비지 막대, 통계, 승률 막대(모델이 있을 때) | 효과음, 애니메이션, 리플레이 |
| 키 설정(고정값, 코드에서 바꿈), DAS/ARR | 설정 화면 |

옛 `Board`, `Shape`, `Tetrominoes`, `Tetris`(분기점 1 이전의 1인용 화면)는 지운다(10-04 결정). git 기록에는 남는다.

## 2. 구조

```
core      규칙 (시간 없는 GameModel, 배치 탐색, 고정 처리)          ← 이미 있음
core      TimedPlayer, TimedMatch: 실제 시간 규칙 (RULES 6.3, 12.3)   ← 새로
ai        Brain: 배치 고르기 (점수 매기기 + 온도 + 2수 탐색)           ← MatchRunner 에서 떼어 냄
ai        AiController: 생각 지연·초당 입력으로 목표 배치까지 조작      ← 새로
ai        AiCatalog: 난이도·페르소나 → 모델 파일 (models/manifest.json) ← 새로
ui        Swing 화면: 메뉴, 대전 화면, 키 입력                         ← 새로
train     MatchRunner, MatchMain (블록 동기 학습 대전)                 ← Brain 을 쓰도록만 바꿈
```

- **규칙과 화면을 나눈다.** `TimedMatch`는 화면 없이 1ms 틱으로 돈다. 화면은 실제 시간이 흐른 만큼 틱을 돌리고 상태를 그린다. 같은 코드가 헤드리스 시험(가상 시간 모드)에서도 돈다.
- **결정론.** 같은 시드, 같은 입력 열이면 같은 결과가 나온다(사람 입력은 틱 번호와 함께 들어간다). AI의 고르기 난수는 학습 대전과 같은 스트림(`Chooser`, 101·102)을 쓴다.

## 3. 실제 시간 규칙 (RULES 6.3 확정분)

RULES 6.3의 `[초안]`을 아래처럼 정한다. RULES 6.3에도 같은 내용을 옮긴다.

### 3.1 한 틱 (1ms)

한 플레이어의 한 틱은 **입력 → 중력 → 락 딜레이** 순서다(RULES 12.3).

1. **입력:** 조작 하나(없을 수도 있음). `L`, `R`, `CW`, `CCW`, `D`(한 칸), `HD`(하드드롭), `H`(홀드). 하드드롭은 그 자리에서 고정하고 이번 틱의 나머지(중력, 락 딜레이)는 하지 않는다. 홀드는 블록 하나당 한 번이고, 성공하면 새 블록이 스폰 상태로 나온다(RULES 4장).
2. **중력:** `acc += g`(소프트드롭을 누르고 있으면 `max(g, 20000)`). `acc ≥ 1,000,000`이면 `acc −= 1,000,000`하고 한 칸 내린다(한 틱에 많아야 한 칸). 바닥에 닿아 있으면 `acc = 0`.
3. **락 딜레이:** 아래 3.2.

### 3.2 락 딜레이

| 항목 | 정함 |
|---|---|
| 타이머 시작 | 블록이 **바닥에 닿지 않은 상태에서 닿은 상태로 바뀔 때** 500ms로 놓는다. 스폰하자마자 바닥에 닿아 있으면 스폰 때 놓는다 |
| 줄어듦 | 바닥에 닿아 있는 틱마다 1씩. 0이 되는 틱에 고정한다(바닥에 닿은 지 500틱째) |
| 떨어졌다가 다시 닿음 | 떨어져 있는 동안 타이머는 멈추고, 다시 닿을 때 500ms로 다시 놓는다. 리셋 횟수는 늘지 않는다 |
| 리셋 | 바닥에 닿은 상태에서 이동·회전에 **성공**하면 타이머를 500ms로 되돌리고 리셋 횟수 +1. 실패한 조작은 아무것도 바꾸지 않는다(RULES 6.1) |
| 15회 | 리셋 횟수가 15가 되면, 그 뒤로는 바닥에 닿아 있는 틱의 끝에 바로 고정한다. **15번째 리셋은 시간을 주지 않는다** |
| 리셋 횟수 되돌림 | 블록의 가장 아래 칸의 행 번호가 그 블록의 최댓값보다 커지면 0으로 |

- 스폰 지연, 줄 삭제 지연은 0ms(RULES 6.3).
- **T-spin:** 사람이 둔 블록도 고정할 때 RULES 8장으로 판정한다. 중력으로 내려가거나 `D`로 내려가면 "마지막 조작"이 이동이 되고, 거리 0인 하드드롭은 바꾸지 않는다(RULES 6.1). 그래서 회전으로 끼운 뒤 바로 하드드롭하거나 락 딜레이로 고정하면 T-spin이 된다.

### 3.3 두 플레이어 (RULES 12.3)

- 한 틱에 P1을 처리한 뒤 P2를 처리한다. 틱 안에서 생긴 송신은 **틱이 끝날 때** 상대 대기열에 붙인다.
- 패배는 두 플레이어의 처리가 끝난 뒤 판정한다. 같은 틱에 둘 다 지면 무승부.
- **중력 단계:** 판 시작 후 30초마다 한 단계(RULES 6.3 표), 그 판의 상한까지. 상한은 고른 난이도로 정하고 두 플레이어에게 같다(PLAN 7장).
- **혼자 연습:** 플레이어 하나와 가비지 스케줄러. 스케줄러는 `없음`, `S-3`, `S-mix`(RULES 13장) 중 고른다. 중력 상한은 고른 단계.

## 4. 사람의 입력

| 동작 | 기본 키 | 처리 |
|---|---|---|
| 왼쪽 / 오른쪽 | ← / → | 누르는 틱에 한 번, **DAS** `[초안] 170ms` 뒤부터 **ARR** `[초안] 50ms`마다 반복. 반대쪽을 누르면 나중에 누른 쪽만 |
| 소프트드롭 | ↓ | 누르고 있는 동안 중력 `max(g, 20000)` (RULES 6.3) |
| 하드드롭 | Space | 누를 때 한 번 |
| 시계 / 반시계 회전 | ↑ 또는 X / Z | 누를 때 한 번 |
| 홀드 | C 또는 Shift | 누를 때 한 번 |
| 일시정지 / 메뉴 | P / Esc | P는 혼자 연습만 일시정지. Esc는 혼자 연습이면 바로 메뉴, 대전이면 2초 안에 한 번 더 눌러야 기권하고 메뉴 |
| 전체 화면 | F11 | 테두리 없는 전체 화면을 켜고 끈다(발표용). 켠 채 시작하려면 `.\gradlew.bat run "-Dtetris.fullscreen=true"`(PowerShell에서는 따옴표가 필요하다). 창이 화면보다 크면 처음부터 최대화한다 |

- 키 입력은 Swing `KeyEvent`로 받아 "눌림/뗌" 상태를 갱신하고, 틱을 돌릴 때 그 상태에서 조작을 만든다(한 틱에 조작 하나, RULES 12.3).
- 키 반복(운영체제의 자동 반복)은 **모든 키에서** 무시하고(누른 키는 뗄 때까지 다시 누른 것으로 치지 않는다) DAS/ARR만 쓴다. 그래서 Space를 누르고 있어도 하드드롭은 한 번이다.
- 시작 카운트다운(3·2·1) 동안 누른 게임 키는 버린다. 시작하자마자 한꺼번에 실행되지 않게 하기 위해서다.
- 게임 화면과 메뉴는 입력기(IME)를 끈다. 한/영이 '한'이어도 Z·X·C·P가 입력기에 먹히지 않는다.

## 5. AI 조작기 (PLAN 4.3)

AI는 사람과 같은 규칙 안에서 조작한다. 블록마다:

1. **생각:** 블록이 고정되고 새 블록이 나오면 **생각 지연** 동안 아무 입력도 하지 않는다. 지연이 끝나는 틱에 `Brain`이 그 순간의 위치(중력으로 내려왔을 수 있다)에서 내 상태와 상대 상태로 목표 배치를 고른다(학습 대전과 같은 점수 매기기, 온도, 2수 탐색). AI가 계획대로 홀드해서 꺼낸 블록은 같은 계획을 이어 가므로 다시 생각하지 않는다.
2. **실행:** 목표의 **칸 집합과 spin**(정규화 키에서 홀드 표시를 뗀 부분)을 고정한다. 입력 간격(1000 ÷ 초당 입력 ms)마다, 그 순간의 블록 위치에서 배치 탐색(RULES 14장)을 다시 해 목표까지의 경로를 구하고 **첫 조작 하나만** 한다. 목표가 홀드 배치면 첫 조작은 `H`다. 목표에 도착하면(경로가 비면) 하드드롭한다.
3. **재결정:** 중력·락 딜레이 때문에 목표에 갈 수 없게 되면(현재 위치에서 탐색한 결과에 목표가 없으면), 생각 지연 없이 현재 위치에서 다시 고른다. 이미 홀드를 썼으면 홀드 배치는 후보에서 빠진다(GameModel 이 빼 준다).
4. **기록:** 목표를 한 번이라도 바꾼 블록 수 ÷ 블록 수 = **실행 실패율**. 레벨별 5% 이하가 목표다(PLAN 4.3). 헤드리스 가상 시간 시험으로 잰다.

- 생각과 탐색은 게임 진행 스레드에서 한다. 2수 탐색도 결정 하나에 수십 ms라, 그동안 늦은 틱은 바로 따라잡는다(화면 스레드는 멈추지 않는다).
- 고정한 뒤 다음 블록까지의 지연은 생각 지연 하나뿐이다.

## 6. 난이도와 페르소나

### 6.1 난이도 5단계 `[초안]`

조작 속도와 중력 상한은 PLAN 7장에서 출발했고, 1~3단계는 10-04에 약 20% 늦췄다(표 아래 메모). **두뇌는 학습량**으로 나눈다(TRAINING 11.1). 모델은 난이도 사다리(`runs/ladder01`, `runs/ladder02`, 블록 동기 모드 200판)를 보고 골라 `python/tools/make_bundle.py`의 표에 적었다(10-04).

| 단계 | 이름 | 두뇌 (학습량) | 온도 τ | 탐색 | 기준 AI 상대 (블록 동기) | 생각 지연 | 초당 입력 | 중력 상한 |
|---|---|---|---|---|---|---|---|---|
| 1 | 초급 | `r01` 세대 0 (학습 전, 기준 평가만) | 0.2 | 1수 | 0.165 | 1,450ms | 5 | 초당 2칸 |
| 2 | 중급 | `r01` 세대 10 | 0 | 1수 | 0.675 | 700ms | 6 | 초당 3칸 |
| 3 | 상급 | `r01` 세대 38 | 0 | 1수 | 0.755 | 400ms | 10 | 초당 5칸 |
| 4 | 최상급 | `a2` 세대 52 (`r01` 38세대 + 이어 학습 14세대, β 0.01) | 0 | 1수 | 0.900 | 180ms | 16 | 초당 8칸 |
| 5 | 불가능 | `a2` 세대 52 | 0 | 2수(`beam` 8) | 0.985 | 100ms | 25 | 초당 12칸 |

- **10-04 사용자 조정.** 해 보니 어렵다고 해서 1~3단계의 조작 속도만 약 20% 늦췄다(생각 지연 900/500/300ms → 1,450/700/400ms, 초당 입력 5/8/12 → 5/6/10). PLAN 7장대로 느림은 생각 지연으로 만들고 초당 입력은 5 이상으로 둔다. 두뇌, 온도, 중력 상한, 4·5단계는 그대로다. 같은 날 단계 이름을 입문·초급·중급·상급·고수에서 **초급·중급·상급·최상급·불가능**으로 바꿨다(사용자 결정). 메뉴에서 처음 고른 단계는 2단계 중급이다.

- **온도는 PLAN 7장보다 훨씬 작다.** `Chooser`는 점수를 표준편차로 나눈 뒤 τ로 소프트맥스하므로 τ 0.3만 돼도 학습 전 모델의 승률이 0.04로 떨어진다(τ 0.05 0.465, 0.1 0.42, 0.2 0.165, 0.5 0.005, 1.0 0). PLAN 7장의 1.0 / 0.7 / 0.4 / 0.2는 쓰지 않는다.
- 사람이 느끼는 난이도는 조작 속도(초당 블록 수)가 가장 크게 정한다(PLAN 7장). 가상 시간 모드로 잰 단계별 실행 실패율·초당 블록 수·이웃 단계 승률은 6.4.

### 6.2 페르소나

- 페르소나는 **학습 방향**(스타일 보상)이 다른 모델이다(TRAINING 9장). 메뉴에서 `중립`(난이도 사다리의 모델)과, 페르소나 학습으로 만든 게임용 파일(`value_<페르소나>_gen-XXX.onnx`) 중에서 고른다.
- 페르소나를 고르면 **두뇌만** 그 페르소나 모델로 바꾸고, 온도·탐색·조작 속도·중력 상한은 고른 난이도를 따른다.
- **지금 묶음의 페르소나 (10-04):** 중립 + 페르소나 본 학습 `p04` 세대 10의 원형 AI 넷(공격형·수비형·T-spin형·콤보형). 고른 이유와 확인은 TRAINING 9.9. 이 모델들은 실력이 4단계 두뇌(`a2` 세대 52)와 비슷하므로(쓰지 않은 시드 200판에 0.505~0.575), **페르소나는 4·5단계(최상급·불가능)에서만 고른다**(10-04 사용자 결정, 모델 묶음의 난이도마다 `"personas": true/false`). 메뉴의 안내 문구("페르소나는 최상급·불가능에서 고를 수 있어요")도 이 값에서 단계 이름을 가져온다. 그 아래 단계에서는 메뉴의 페르소나 줄이 잠기고 중립을 쓴다. 그래서 "난이도 = 학습량"이 그대로 지켜진다.
- **메뉴는 가볍게** (10-04 사용자 결정): 난이도는 짧은 한 줄(예: "빠르고 정확한 AI")과 강도 막대, 페르소나는 무엇을 좋아하도록 배웠는지 한 줄(예: "T-spin을 노리도록 배운 AI")만 보인다. 학습 세대, 생각 지연·초당 입력 같은 자세한 정보와 시험 결과(확실한 행동 차이는 T-spin형뿐)는 문서(TRAINING 9.9, 11.1, 이 문서 6.1)에만 둔다.

### 6.3 모델 묶음 `models/manifest.json`

게임은 저장소의 `models/` 폴더에서 모델을 찾는다. 파일이 없거나 꼬리표(`tetris.model_io`, `tetris.rules`)가 맞지 않거나 ONNX Runtime이 없는 PC면 **기준 AI(`BaselineScorer`)로 대신**하고 메뉴에 표시한다.

```json
{
  "format": "models-1",
  "difficulties": [
    {"id": 1, "name": "초급", "model": "value_r01-g000.onnx", "temperature": 0.2, "beam": 0,
     "think_ms": 1450, "inputs_per_sec": 5, "gravity_cap": 2},
    ...
  ],
  "personas": [
    {"id": "neutral", "name": "중립", "model": null},
    {"id": "attacker", "name": "공격형", "model": "value_attacker.onnx"},
    ...
  ],
  "winprob": "winprob.onnx"
}
```

- `model`은 `models/` 기준 경로, `"baseline"`이면 기준 AI다. 중립 페르소나(`model: null`)는 난이도의 모델을 쓴다.
- `gravity_cap`은 RULES 6.3 표의 단계 번호가 아니라 **초당 칸 수**다. 그 값을 넘지 않는 가장 높은 단계까지 올라간다.
- **`models/`는 git에 넣는다** (10-04 사용자 결정). 팀원이 저장소를 받자마자 학습한 AI로 게임할 수 있다. 묶음은 `python/tools/make_bundle.py --p04-personas`가 `runs/`에서 복사해 만든다(가치망 4개 약 2.8MB + 페르소나 4개 약 2.8MB, 승률 모델 0.85MB). `runs/p04/personas/`의 자동 이름 파일은 이름이 설계와 맞지 않아 쓰지 않는다(TRAINING 9.9).

### 6.4 가상 시간 모드 측정 (10-04, `gradlew levelBench`)

`models/`의 다섯 단계를 가상 시간 모드(RULES 12.3)로 대전시켰다. 같은 단계끼리 40판(그 단계의 중력 상한), 이웃한 단계끼리 40판(시드마다 자리를 바꿔 두 판, 위 단계의 중력 상한). 시드는 `950001`부터. 1~3단계를 늦춘 뒤(6.1) 같은 시드로 다시 쟀다. 결과는 `runs/levels03/levels.json`이고, 늦추기 전의 결과는 `runs/levels01/`에 있다(괄호 안).

| 단계 | 실행 실패율 (목표 5% 이하) | 초당 블록 수 (늦추기 전 / PLAN 7장 추정) | 같은 단계끼리 평균 판 길이 (늦추기 전) | 바로 아래 단계 상대 승률 (늦추기 전) |
|---|---|---|---|---|
| 1 초급 | 0.02% (0.07%) | **0.39** (0.50 / 0.5) | 128초 (110초) | |
| 2 중급 | 0% | **0.61** (0.79 / 0.8) | 169초 (124초) | 1.000, 40승 0패 (1.000) |
| 3 상급 | 0.02% (0%) | **0.97** (1.18 / 1.25) | 103초 (86초) | 0.975, 39승 1패 (0.950) |
| 4 최상급 | 0.01% (0.01%) | 1.69 (1.69 / 1.8) | 77초 | 1.000, 40승 0패 (0.950) |
| 5 불가능 | 0% | 2.66 (2.66 / 2.9) | 179초 | 0.975, 39승 1패 (0.975) |

- **실행 실패율은 모든 단계에서 목표보다 훨씬 낮다.** 생각 지연 동안 블록이 내려와도, 중력 상한이 낮은 단계는 목표 자리에 가기에 시간이 넉넉하다. 실패는 단계마다 많아야 블록 1~2개다(지금 1단계 4,009블록 중 1, 3단계 8,006블록 중 2, 4단계 1블록. 늦추기 전에는 1단계 3블록, 4단계 1블록).
- **1~3단계의 초당 블록 수는 늦춘 만큼(18~23%) 줄었다.** 4·5단계는 PLAN 7장의 추정과 거의 같다(추정은 블록당 입력 6회를 가정했고, 실제 경로는 그보다 조금 길다).
- **위 단계가 바로 아래 단계를 거의 언제나 이긴다(0.975~1.0).** 블록 동기 모드의 두뇌 차이(TRAINING 11.1)에 조작 속도 차이가 더해졌기 때문이다. 사람이 느끼는 단계 차이도 주로 속도에서 온다.
- 이 측정은 AI끼리의 결과다. 사람 상대 승률(PLAN 7장 목표 90 / 70 / 50 / 30 / 10%)은 사람이 직접 해 봐야 안다.

- 보이는 영역 20행(4~23행)을 그린다. 숨김 영역 아래 두 줄에 걸친 블록(막 나온 블록)은 보드 위 여백에 또렷하게 그린다.
- **고스트:** 하드드롭하면 놓일 자리를 옅은 채움과 밝은 테두리로.
- **받을 가비지 막대:** 보드 왼쪽, 대기 줄 하나에 한 칸. 1~3줄 노랑, 4~7줄 주황, 8줄 이상 빨강으로 깜빡이고 줄 수를 숫자로 보인다.
- **위험 표시:** 쌓인 높이 + 곧 올라올 방해 줄(최대 8) ≥ 15줄이면 보드 테두리가 빨갛게(#FF3B30, AI 색과 구분) 깜빡인다.
- **동작 기록**(홀드 아래 빈 칸, 10-04): 방금 지운 줄의 이름(SINGLE~TETRIS, T-SPIN), B2B·콤보·퍼펙트 클리어 배지, "2줄 → 공격 3", 보너스가 있으면 내역("기본 2 + 콤보 1"), 상쇄됐으면 "상쇄 1 · 보냄 2"를 2.6초 보인다. 보드 안을 가리지 않는다. 퍼펙트 클리어만 보드 가운데에 금색 띠로. 판이 끝나면 그리지 않는다.
- **공격 표시**(과제 3번): 보낸 공격이 "+N" 칩으로 상대의 받을 가비지 막대까지 0.45초 동안 날아가고, 도착한 칸들이 반짝인다.
- **예측 승률**(과제 2번): 막대 13칸 폭, 50% 눈금, 양 끝에 큰 "나 34%" / "66% AI", 값은 약 0.2초에 걸쳐 부드럽게 따라간다. 한 번에 5%p 이상 움직이면 원인 칩("AI ▲ 12%p · 나 방해 줄 4줄")을 1.6초 띄운다. 아래에는 판 동안의 흐름.
- **통계**: 초당 블록(PPS), 공격, 보냄, APP, T-spin. AI 이름 옆에는 생각 지연 동안 차오르는 고리.
- **시작 카운트다운** 3·2·1·GO, **결과 카드**(두 플레이어 통계 비교, 예측 승률 흐름 그래프), 일시정지 카드, Esc 기권 확인 알림.
- **승률 막대**(과제 2번): `WinRate`로 P1이 이길 확률을 블록이 고정될 때마다 다시 잰다(TRAINING 10장). 승률 모델이 없으면 숨긴다. 혼자 연습에서는 없다.
- **판이 끝나면** 결과(승/패/무, 패배 종류), 통계(블록, 공격, 보냄, APP, T-spin, 테트리스, 최대 콤보), "다시 / 메뉴로".
- 메뉴: 모드(사람 대 AI / 혼자 연습) → 사람 대 AI면 난이도와 페르소나, 혼자 연습이면 중력 상한과 가비지 스케줄러 → 시작. 시드는 판마다 시각으로 정하고 결과 화면에 보여 준다.

## 8. 시험

| 대상 | 시험 |
|---|---|
| `TimedPlayer` | 중력 누적(초당 1칸이면 1000틱째 한 칸), 바닥 닿으면 `acc = 0`, 락 딜레이 500틱째 고정, 리셋 15회와 15번째 리셋, 최저 행 갱신으로 리셋 횟수 0, 떨어졌다 다시 닿을 때 타이머, 실패한 조작이 타이머를 안 바꿈, 홀드 한 번만, 하드드롭 즉시 고정, 회전으로 끼우고 하드드롭한 T-spin |
| `GameModel` 실시간 확장 | `lock(PieceState)`와 `apply(Placement)`가 같은 배치에 같은 결과, 홀드 후 `placements()`에 홀드 배치 없음, 블록 도중 상태에서의 배치 탐색 |
| `TimedMatch` | 틱 끝 송신, 같은 틱 둘 다 패배 → 무승부, 중력 단계와 상한, 같은 시드·입력이면 같은 결과 |
| `AiController` | 중력 0에서 목표 배치를 그대로 둠(블록 동기 모드와 같은 배치 열), 생각 지연과 입력 간격 지킴, 빠른 중력에서 재결정, 홀드 배치 실행, 실행 실패율 측정 |
| `Brain` | 학습 대전 기록이 바뀌지 않음(`fixtures/match` 재생, `MatchRunnerTest`) |
| `HumanInput` | 누를 때 한 번, DAS 170ms 뒤 ARR 50ms 마다 반복, 양쪽을 누르면 나중 쪽, 한 번 하는 조작은 빠짐없이 한 틱에 하나, 포커스를 잃으면 모두 뗌 |
| `AiCatalog` | 묶음이 없으면 기준 AI 기본값, 모델 파일이 없으면 기준 AI 로 대신하고 이유를 남김, ONNX 모델 불러오기 |
| 화면 | 배치는 `gradlew screenshot`(창 없이 그린 그림)으로 확인. 키 감각과 체감 난이도는 사람이 직접 해 봐야 한다 |
