## 10. 분기점 2 최종 점검

5단계 문서까지 올린 뒤 두 가지를 했다.

**새로 clone해서 README대로 따라 하기.** `gradlew build`는 통과했지만, `python -m pip install -r python/requirements.txt`가 **한국어 Windows에서 실패**했다. pip이 이 파일을 시스템 코드페이지(cp949)로 읽는데 한글 주석이 UTF-8이었다. 제 가상환경에서는 패키지를 이름으로 직접 설치해 드러나지 않았던 문제다. 파일을 ASCII로 바꾸고 README에 pip 업그레이드 단계를 넣었다.

**독립 리뷰.** 문서 일관성, 코드 버그, 모델 입출력(명세·Java·Python) 세 관점의 리뷰 에이전트 3개가 지적을 내고, 지적마다 다른 에이전트가 반박을 시도했다(총 23개). 반박을 견딘 18건과 경미한 지적 대부분을 고쳤다.

| 분야 | 고친 것 |
|---|---|
| 플랫폼 | ONNX Runtime 1.30 jar에는 **Intel Mac용 실행 파일이 없다**(jar 내용으로 직접 확인). 지원하지 않는 PC에서는 ONNX 테스트를 건너뛰고 게임은 휴리스틱으로 대신하게 했다. 이 보고서가 Apple Silicon을 걱정했던 것은 거꾸로였다 |
| README | PowerShell은 `.\gradlew.bat`처럼 경로가 필요, 가상환경 활성화에 실행 정책 설정 필요, macOS는 `python3.11` 명령 |
| 모델 실행 | 불러올 때 입력·출력의 자료형과 모양까지 확인(PyTorch에서 흔한 `[N]` 출력 거부). 실행 중 모든 오류를 약속된 `IllegalStateException`으로 바꿔 휴리스틱 대체가 확실히 일어나게 함. 옵션 객체 누수, 두 번 닫기 |
| 모델 입력 | 미리보기를 5개보다 길게 넘기면 **아직 안 보인 6번째 블록이 입력에 섞일 수 있던** 문제 수정 |
| 명세 충돌 | RULES는 "모델 입력의 콤보·B2B는 놓기 전 값", MODEL_IO는 "놓은 뒤 값"이라고 달랐다. 모델은 놓은 뒤 값으로 통일. 모델 출력 `value`가 즉시 보상까지 포함한 최종 점수임을 명시(PLAN 9.1과 일치). 락 아웃 배치는 후보에서 뺀다고 명시 |
| 테스트 | 빠진 필드를 조용히 통과시키던 곳 보강, 거부 시험 모델 2개 추가, 실제로 나올 수 없던 시험 사례(`big-combo`) 수정 |
| 기타 | 22행 시절 예시와 주석, 로캘에 따라 달라지는 대소문자 변환, 내부 배열 노출, 벤치마크의 블록 아웃 검사 순서, 문서 번호·개수 오류 |

반박된 지적 2건(가비지 구멍 상태 복원, 홀드 탐색 입력)은 현재 코드에서 실제 문제가 생기지 않아 고치지 않았다.
